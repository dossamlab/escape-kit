# 개발 이력

`audit-room`·`relayout-room` 스킬이 마무리 단계에서 여기에 기록한다.
**찾은 것뿐 아니라 "확인했는데 문제 없던 것"까지** 적는다 — 다음 점검의 범위가 된다.

형식은 자유롭되 날짜 헤딩(`## YYYY-MM-DD — 무엇을 했나`)으로 시작한다.

---

## 2026-08-07 — 저작 키트로 분리

물리 방탈출(1막 5방 / 2막 3방)에서 **엔진과 저작 도구만** 떼어 낸 시점.
예제로 방 하나(청음실, 탄성파와 소리)를 남기고 나머지 콘텐츠는 비공개 저장소에 두었다.

이때 함께 정리한 것:

- 세계관 문자열을 `src/config.ts`로 모음 (엔진과 main에 흩어져 있던 8개)
- 아이템 정의를 `src/engine/core/inventory.ts` → `src/data/items.ts`로 이동
  (콘텐츠가 engine/ 안에 살면 "엔진은 안 건드린다"는 약속이 깨진다)
- `gate.keys[].freq`를 선택 사항으로 — 답의 도메인을 숫자·음이름 밖으로 열었다
- `scripts/check-anchors.mjs` 추가 + `verify.sh` 편입 (앵커 오타가 무음으로 지나가던 구멍)
- `playwright.config.ts`의 `reuseExistingServer`를 **false**로.
  true였을 때 같은 포트에 떠 있던 **다른 저장소의 개발 서버**를 물고
  32개가 "실패"했다. 조용히 틀린 앱을 재느니 포트 충돌로 죽는 편이 낫다.
- 개발/테스트 포트 분리: 5373 / 5399
- **`map:enter`가 첫 방에서도 발화하도록** (`Game.start()` 끝). 전에는 `switchMap`에서만
  쐈기 때문에, 예제 방이 두 번째 방일 때는 멀쩡하다가 **첫 방이 되자 룸 오디오·HUD 미터가
  통째로 죽었다**(퍼즐 스펙 16개 실패). 방 수준 연출을 쓰는 방을 앞으로 옮기면 누구나 밟는다.
  대신 구독은 `new Game(...)` **전에** 해야 한다 — main.ts의 `registerRoomFx`가 그 자리다.

문제 없던 것: 엔진 21개 파일 중 교과에 물든 곳은 위 셋뿐이었다.
`PuzzleApi`·`GameMap`·story.md 파서·이미지 파이프라인은 손댈 것이 없었다.
