처음 오신 분께

컴퓨터를 잘 몰라도 만들 수 있습니다

선생님이 하는 일은 교과를 판단하는 것입니다. 코드는 Claude Code가 씁니다. 아래 다섯 칸이 컴퓨터 앞에서 실제로 하는 전부입니다.

이 키트는 Claude Code 기준으로 만들었습니다. 게임 자체는 어떤 도구로도 고칠 수 있지만, 저작 절차 여섯 개와 안전장치(에셋 색을 정해진 팔레트 밖으로 못 쓰게 막는 것, 세션마다 진행 상황을 되짚어 주는 것)가 Claude Code 위에 얹혀 있습니다. 다른 AI 코딩 도구로 못 쓸 것은 없지만, 끝까지 검증된 길은 이쪽 하나입니다.

명령어를 외우지 않습니다

이 문서의 회색 상자는 전부 복사해 붙여넣으라는 뜻입니다. 상자를 통째로 긁어 창에 붙이고 엔터를 치면 됩니다.

코드를 읽지 않습니다

퍼즐도 대사도 Claude Code가 씁니다. 선생님은 "이 개념이 맞는가", "학생이 이걸 풀 수 있는가"만 판단하면 됩니다.

잘못해도 되돌아갑니다

모든 변경은 기록으로 남습니다. "방금 것 되돌려 줘"라고 말하면 직전 상태로 돌아갑니다.

막히면 그대로 붙여넣습니다

빨간 글씨가 뜨면 읽으려 애쓰지 마세요. 통째로 복사해 붙여넣고 "이거 어떻게 해?"라고 물으면 됩니다.

학생은 아무것도 깔지 않습니다

완성된 게임은 주소 하나입니다. 휴대폰에서도 열립니다. 서버도 회원가입도 없습니다.

얼마나 걸리나요

준비는 30분 안쪽입니다. 방 하나는 퍼즐 4~5개입니다. 퍼즐 하나에 대화 몇 번이 오갑니다.

바로 아래에 처음부터 끝까지 순서대로 무엇을 치는지가 있습니다. 그다음부터는 같은 이야기를 자세히 적은 것이니, 필요할 때 해당 단계만 찾아 보시면 됩니다.

그대로 따라 치기

처음부터 끝까지, 순서대로 무엇을 치는가

위에서 아래로 한 줄씩 내려가면 방 하나가 완성됩니다. 회색 상자를 누르면 복사됩니다 — 창에 붙여넣고 엔터를 치세요. 점선 상자는 명령이 아니라 Claude Code에게 말로 하는 것이라, 표현이 조금 달라도 됩니다.

Claude Code는 터미널로도 쓰고 데스크탑 앱으로도 씁니다. 두 길은 순서가 다르니 아래에서 자기 쪽을 고르세요. 검은 창을 한 번도 안 써 보셨다면 데스크탑 앱입니다.

검은 창(터미널·명령 프롬프트)에 직접 칩니다. 회색 상자가 그대로 칠 명령입니다.

  1. 준비 — 평생 한 번

    두 프로그램을 받아 깝니다. 내려받아 실행한 뒤 확인만 누르면 됩니다. Node.js(LTS 버전)와 Claude Code입니다.

  2. 터미널

    키트를 내려받습니다. my-escape 폴더가 생깁니다.

  3. 터미널

    방금 만든 폴더 안으로 들어갑니다. 이제부터 모든 명령은 이 안에서 칩니다.

  4. 터미널

    필요한 부품을 받습니다. 처음 한 번만이고 몇 분 걸립니다.

  5. 터미널

    그림 파일을 만듭니다. 이걸 건너뛰면 화면이 검게 나옵니다.

  6. 터미널

    예제 방이 열립니다. 주소 http://localhost:5373을 눌러 한 바퀴 돌아 보세요. 이 창은 끄지 말고 켜 둡니다. 다음 명령은 터미널 창을 하나 더 열어서 칩니다.

  7. 여기부터 선생님의 교과

    새 터미널 창을 열고 같은 폴더로 들어간 다음(cd my-escape), Claude Code를 켭니다.

  8. 터미널

    Claude Code가 켜집니다. 앱으로 쓰신다면 앱에서 my-escape 폴더를 열면 같습니다. 반드시 이 폴더에서 열어야 아래 명령들이 살아납니다.

  9. Claude Code

    교과를 갈아끼웁니다. 딱 한 번만 칩니다. 곧바로 질문이 시작됩니다.

  10. Claude Code

    질문에 이렇게 답하면 됩니다. 교과·학년, 성취기준 원문, 인물 한 사람, 방 개수 넷이 핵심입니다. 성취기준은 기억으로 적지 말고 원문을 붙여넣으세요 — 코드를 지어내지 않는 것이 이 키트의 규약입니다.

  11. Claude Code

    여기서 품질이 갈립니다. 이 10개가 검수자에게 상수로 박혀, 앞으로 만드는 모든 퍼즐이 그 검수를 통과해야 합니다.

  12. Claude Code

    퍼즐을 하나 만듭니다. 설계를 보여 주면 읽고 승인하시면 됩니다. 방 하나에 4~5번 반복합니다. 다음 퍼즐도 같은 명령입니다.

  13. Claude Code

    설계가 마음에 안 들면 이렇게 되돌립니다. 승인하기 전에는 얼마든지 되돌릴 수 있습니다.

  14. Claude Code

    퍼즐을 다 만든 뒤 한 번 칩니다. 학습자 눈으로 방 전체를 훑어 어색한 곳을 찾아냅니다.

  15. 학생에게 주기

    다시 터미널입니다. 첫 줄은 처음 한 번만 칩니다(수백 MB를 받습니다).

  16. 터미널

    검사에 쓸 브라우저를 받습니다. 처음 한 번만입니다.

  17. 터미널

    컴퓨터와 휴대폰 화면 양쪽에서 방을 끝까지 자동으로 깨 봅니다. 전부 초록이어야 완성입니다. 빨간 줄이 뜨면 통째로 복사해 Claude Code에 붙여넣으세요.

  18. 터미널

    dist 폴더가 만들어집니다. 이 폴더를 학교 홈페이지나 무료 호스팅에 그대로 올리면 주소 하나가 됩니다. 학생은 설치 없이 그 주소만 열면 됩니다.

  19. 막혔을 때

    빨간 글씨를 해석하려 애쓰지 마세요. 화면에 뜬 글을 통째로 복사해 Claude Code에 붙여넣고 아래처럼 물으면 됩니다.

  20. Claude Code

    되돌리고 싶을 때는 "방금 한 것 되돌려 주세요"라고 하면 직전 상태로 돌아갑니다.

  8. 여기부터 선생님의 교과

  10. Claude Code

    질문에 이렇게 답합니다. 성취기준 문서가 파일로 있다면 프롬프트 상자에 끌어다 놓아도 됩니다.

곁들이면 좋은 것

대사가 "만든 티"가 날 때 — 한글 윤문 스킬

이 키트에서 학생이 읽는 글은 전부 docs/story.md에 있습니다. 대사, 연구노트, 수색했을 때 나오는 문장. AI가 쓴 한국어는 밋밋해지기 쉽습니다 — 학생은 이유를 대지 못하면서도 "기계가 쓴 것 같다"고 느낍니다.

im-not-ai의 humanize-korean 스킬이 그걸 잡아 줍니다. 번역투·기계적 병렬·접속사 남발 등 10개 갈래 70여 개 패턴을 찾아 내용은 그대로 두고 문체만 고쳐 씁니다. 키트에 넣지 않았으니, 필요한 분만 두 줄로 깔면 됩니다.

    스킬 보관소를 등록합니다. 데스크탑 앱이라면 + 버튼 → Plugins → Add plugin으로 명령 없이 골라 깔 수도 있습니다.

  2. Claude Code

    설치합니다. 다음 세션부터 쓸 수 있습니다.

  3. Claude Code

    다듬은 뒤에는 npm run story를 한 번 치고, 게임에서 대사를 눈으로 확인하세요.

앵커는 건드리지 않게 하세요

### #앵커 줄은 코드가 대사를 찾는 이름표입니다. 인용 줄(>)만 다듬으라고 일러 주세요. 오타가 나면 npm run anchors가 잡습니다.

퍼즐 답이 든 문장은 빼세요

정답을 가리키는 넛지 문장은 단어 하나가 곧 단서입니다. 문체를 고치다 단서가 흐려지면 학생이 풀 수 없습니다.

키트에는 안 들어 있습니다

따로 만든 도구라 설치한 사람만 쓸 수 있고, 갱신도 그쪽을 따라갑니다. 이 키트는 여전히 Node.js 하나만 있으면 됩니다.

한 눈에

다섯 단계, 그리고 하나의 반복

전체 작업은 다섯 덩이다. 이 가운데 세 번째만 여러 번 돈다 — 퍼즐 하나마다 설계부터 실플레이까지 한 바퀴다. 나머지 넷은 방 하나에 한 번씩이다.

03만 반복한다. 02는 되돌리려면 git이 필요한 파괴적 단계라 한 번만 실행한다.

01 · 설치

clone부터 하고 그 폴더에서 Claude Code를 연다

순서가 중요하다. 스킬은 저장소 안 .claude/에 들어 있어서 폴더를 연 뒤에야 로드된다. 링크만 주고 "이걸로 만들어 줘"라고 하면 스킬이 없는 상태로 시작한다. 

git clone https://github.com/dossamlab/escape-kit.git my-escape
cd my-escape && npm install && npm run assets && npm run dev

http://localhost:5373이 열린다. 예제 방을 한 바퀴 돌아 보라. 암전에서 시작해 진자를 흔들어 불을 켜고 벽을 두드려 테이프를 찾는다. 소리가 죽는 자리를 걸어서 찾고 현을 짚어 배음을 낸 다음, 마지막에 네 음을 연주하면 문이 열린다. 어떤 저작 도구든 결국 이 한 바퀴를 만드는 일이다 — 먼저 플레이해 보는 것이 가장 빠른 설명이다.

개발 서버가 뜨면 주소 밑에 그리드 창 주소가 하나 더 찍힌다. 방의 좌표를 손으로 세지 않게 해 주는 창이다 — 아래 03단계에서 다룬다.

02 · 교과 갈아끼우기

/new-subject — 인터뷰 한 번으로 뼈대가 선다

Claude Code에 /new-subject라고 치면 인터뷰가 시작된다. 최초 1회만 실행한다. 물리 예제의 방·퍼즐·스토리를 지우므로, 되돌리려면 git이 필요하다는 확인을 먼저 받는다.

묻는다

교과 · 성취기준 · 화자 · 규모 · 답의 형태

  • 성취기준은 원문을 붙여넣거나 출처 URL을 준다. 기억으로 코드를 지어내지 않는 것이 이 키트의 규약이다 — 확인 전에는 매핑표에 (코드 검증 예정)으로 남는다.
  • 화자는 그 교과의 인물이다. 교사가 직접 설명하지 않고 그 인물이 남긴 기록이 말하게 한다. 세종이 남긴 주석, 퀴리의 실험 일지, 사마천의 사초 — 화자를 정하면 방에 놓일 사물과 연구노트가 따라온다.
  • 규모는 방 1개를 권한다. 퍼즐 4개 + 최종 콘솔 1개가 표준이다.
채굴

학생이 가장 많이 틀리는 것 10개 — 여기서 품질이 갈린다

"이 단원에서 학생들이 가장 많이 틀리는 사실·표기·연표·수치·개념 혼동을 10개만 적어 주세요." 이 10개가 다음 단계에서 만들어지는 교과 검수 에이전트의 프롬프트에 상수로 박힌다. 이후 모든 퍼즐이 그 검수를 통과해야 한다.

동봉된 physics-reviewer.md가 그 형식이다 — 발머 계열 파장 656/486/434/410 nm처럼 틀리면 바로 알 수 있는 값을 프롬프트가 직접 들고 있다.

산출

다섯 가지가 만들어진다

  • .claude/agents/<교과>-reviewer.md — 오답 10개가 박힌 검수자
  • docs/curriculum-map.md — 성취기준 ↔ 퍼즐 매핑표 (+ 출처, 범위 밖 예외 표)
  • docs/story.md — 화자 모티브 스토리 뼈대
  • docs/puzzles/room1-overview.md — 방 슬레이트와 코드 조각 배정표
  • src/config.ts — 제목 · 저장 키 등 세계관 문자열

답이 꼭 숫자일 필요는 없다

최종 잠금은 세 단계 중에서 고른다. 화면에 보이는 것은 내부 표현이 아니라 키에 붙인 라벨이다 — 동봉 예제가 그 실증이다. 코드는 "1365"인데 학생이 보는 것은 건반의 도·미·라·솔이다.

단계만드는 법쓸 수 있는 답비용
① 숫자 키패드 manifest에 gate.code만 적는다 숫자 0
② 라벨 키패드 gate.keys로 키에 아무 글자나 자모 · 한자 · 연도 · 시대명 · 화학기호 · 사건 이름 몇 줄
③ 콘솔 퍼즐 최종 장치에 gate 없이 puzzleId만 주고 그 퍼즐의 reward.event를 문이 기다리게 한다 형태 제한 없음 — 연표 배치 · 자모 조합 · 주기율표 · 지도 퍼즐 하나

③의 실증은 한국사 드라이런의 '연대 정리대'다. 키패드 대신 시대 패 여덟 중 넷을 골라 연대순으로 놓는 퍼즐이 곧 자물쇠였다.

03 · 반복하는 한 바퀴

/add-puzzle — 설계에서 실플레이까지

퍼즐 하나가 이 순서를 통째로 돈다. 되돌아가는 화살표가 셋 있다는 점이 중요하다 — 승인·검수·실플레이는 통과할 때까지 앞으로 못 간다.

점선 셋이 전부 구현으로 돌아온다. 설계로는 승인 전에만 돌아간다.

퍼즐 하나는 폴더 하나다

manifest.json + puzzle.ts + puzzle.css + autoplay.ts 네 파일이 한 세트다. src/registry.ts에 등록해야 로드된다. 엔진은 퍼즐 내부를 모르고 퍼즐은 엔진 내부를 모른다 — 둘 사이에는 PuzzleApi 하나만 있다.

정답 상수는 autoplay.ts에만 둔다. 테스트가 거기서 가져다 쓰므로 spec에 답을 다시 적지 않는다. 답을 고칠 때 두 곳을 고쳐야 하면 언젠가 한 곳을 잊는다.

대사와 연구노트는 코드에 넣지 않는다

전부 docs/story.md에 있다. ### #앵커 다음의 > 인용 줄이 대사 한 건이다. 코드는 그 앵커 문자열로만 텍스트를 참조한다. 새 대사가 필요하면 story.md에 앵커를 추가하고 npm run story. 앵커 오타는 런타임에 조용하므로 검산 스크립트가 대신 잡는다.

03과 함께 · 방 배치

좌표는 그리드 창에서 찍는다 — 눈대중하면 틀린다

화면에서 픽셀을 눈으로 읽으면 어긋난다. 실측으로 45px(약 0.85타일)까지 틀렸다. 그래서 배경 그림 위에 격자를 얹어 놓고 못 걷는 칸을 마우스로 칠하고 장치 자리를 클릭해서 찍는 창이 들어 있다. 

npm run dev         # 개발 서버 주소 밑에 그리드 창 주소가 같이 찍힌다
npm run tiles       # 주소 + 열기 전 조건(배경 PNG · 개발 서버)을 미리 검사
npm run tiles:open  # 조건이 맞으면 브라우저까지 띄운다

열면 지금 맵의 걷기 금지 칸이 이미 칠해진 채로 뜬다. 백지에서 시작하지 않는다. 「맵 상태로 되돌리기」로 언제든 원상복구, 「전부 지우기」는 빈 판이다. 빨강이 못 걷는 칸, 초록이 시작 위치, 노랑이 장치, 파랑이 연구노트다.

마지막 칸이 가장 중요하다. blocks를 늘리다 보면 어느 순간 구역 하나가 통째로 막히는데, 그 구역을 걷는 테스트가 없으면 타입 검사에도 e2e에도 안 잡힌다. 방을 못 깨는 빌드가 조용히 나갈 수 있다. npm run reach가 스폰에서 모든 오브젝트까지 실제로 걸어 본다.

Claude Code에게 시킬 때도 이 도구를 거치게 하라. "저 책상을 못 지나가게 해 줘"라고만 하면 화면을 눈대중해 좌표를 지어낼 수 있다. /relayout-room 스킬이 위 절차를 그대로 밟는다.

04–05 · 점검과 배포

조용히 실패하는 것만 골라 검산한다

작업이 끝날 때마다 quick, 퍼즐이 완성되면 full. 검산 대상은 틀려도 아무 소리가 안 나는 것들이다 — 앵커 오타, 근접 판정 간격, 도달 가능성. 

bash scripts/verify.sh quick   # 매 작업 후 — 수 초

npx playwright install chromium # 처음 한 번만 (수백 MB)
bash scripts/verify.sh full     # 퍼즐 완성 시 — 데스크톱 + 모바일
명령하는 일언제
npm run dev개발 서버 (5373)늘
npm run tiles그리드 창 주소 + 열기 전 조건 검사좌표를 찍을 때
npm run storystory.md → story-data.ts 재생성대사·노트를 고쳤을 때
e2e 도중에는 금지 — 풀 리로드로 테스트가 죽는다
npm run assetsSVG → PNG (토큰 색 치환 포함)에셋을 고쳤을 때
npm run reach스폰에서 모든 오브젝트에 걸어서 닿는지blocks를 건드렸으면 필수
npm run anchorsstory.md 앵커 참조 검산앵커를 고쳤을 때
npm run build정적 빌드 (dist/, 상대 경로)배포 직전

배포는 정적 파일 복사다

npm run build가 만드는 dist/를 그대로 올리면 된다. base가 상대 경로라 어떤 호스팅의 어떤 하위 경로에서도 돈다 — 학교 홈페이지 하위 폴더든, 무료 정적 호스팅이든, USB에 담아 열든 같다. 서버도 데이터베이스도 필요 없다. 진행 상황은 학생 브라우저에만 저장된다.

먼저 알아 둘 것

전부 실제로 당한 것들이다

e2e 통과 ≠ 화면 정상

SVG 표현 속성 opacity는 CSS에 진다. display:block은 hidden 속성을 덮는다. 테스트의 텍스트 매칭은 숨은 요소의 글자도 잡는다. 시각 요소를 만졌으면 스크린샷을 떠서 눈으로 볼 것.

봉인 안쪽 퍼즐로 봉인을 열 수 없다

봉인 구역을 여는 조건에 그 구역 안의 퍼즐을 걸면 영영 안 열린다. 런타임 검사가 없다. 봉인 범위는 벽 띠까지 덮어야 너머로 반짝임이 새지 않는다.

엔딩 대사를 안 주면 기본값이 나온다

방에 엔딩 앵커를 지정하지 않으면 엔진 기본 대사로 끝난다. 교과를 갈아끼운 방에서 물리 예제의 말투가 나오는 원인이 대개 이것이다.

배경 좌표 보정은 노동이다

생성 이미지 한 장마다 바닥 마름모를 재서 배율과 오프셋을 손으로 넣어야 한다. 스킬이 절차를 문서화해 두었지만 왕복이 생기는 단계다.

검산은 결정적 구조가 있어야 성립한다

순서·대조·짝맞추기처럼 판정이 결정적인 답이면 유일해와 수렴을 테스트가 증명한다. 자유 서술이면 대체 수단은 실플레이뿐이다 — 힌트를 열지 않고 한 번 풀어 보는 절차를 건너뛰지 말 것.

성취기준 코드는 추측해 적지 않는다

웹으로 확인한 뒤에만 매핑표에 적는다. 확인 전에는 검증 예정으로 남긴다. 잘못 적힌 코드는 수업에 쓰이는 순간 교사의 신뢰를 깎는다.

파일 구성과 그렇게 자른 이유는 기초 설계 문서에 있다 — 의존 방향, 단일 소스와 파생물, 정답을 한 곳에 두는 규약, 그리고 치른 대가. 규약 전체는 저장소의 CLAUDE.md가 들고 있다.

이 문서를 파일로 두고 싶으면 저장소의 원본에서 내려받으면 됩니다. 파일 하나로 끝나 인터넷 없이도 열립니다.
