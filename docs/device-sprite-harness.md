## 1. 불변 — 엔진 배선 계약

스프라이트 하나가 화면에 서기까지 거치는 값. **여기 안 맞으면 그림이 아니라 배선이 문제다.**

1. 파일: `assets-src/gen/<이름>.png` (후처리 완료본) → 빌드가 `public/assets/`로 패스스루.
   원본은 반드시 `assets-src/gen-src/<이름>.src.png`에 보존(스킬 4단계 — 덮어쓰면 복구 불가).
2. 배율: `assets-src/asset-scale.json`에 `{"<이름>": 2}` — **정수만**(nearest 확대라
   1.5는 픽셀이 뭉갠다). 화면 높이 = 파일px × 배율 × CAMERA_ZOOM(0.5) = 파일px×1.
3. 맵 배선: `MapObject.sprite: "<이름>"` + **`grounded: true`**(바닥 장치 필수 — 접지
   그림자). 밑면이 넓으면 `sink`(월드 px)로 내려 앉히고, 그림에 다리·받침이 없으면
   `pad`(스프라이트 폭 배율)로 설치 패드를 깐다. 셋 다 `src/maps/types.ts` 주석 참조.
4. 스프라이트 원점: 타일 중심 아래 TILE_H/4가 밑변. 즉 **핫스팟 타일이 곧 설치 위치**다.
5. **타일을 옮기면 재검산이 따라온다** — `check-layout 0.4` + `check-reach`, 그리고
   moveTo 임계값 상한(스테이션 0.4 · 노트 0.8 · 문 1.2, `tests/e2e/helpers.ts`).
   장치가 서면서 시야를 가리면 타일이 아니라 `sink`/크기로 푼다.
6. 장치는 통행을 막지 않는다 — 지금 4자리는 전부 걷는 바닥 위다. 스프라이트가 서면
   그 타일을 밟고 지나가는 게 어색해 보일 때만 **그림에 보이는 밑면만큼** `blocks`를
   추가한다(빈 바닥 블록 = 보이지 않는 벽, 두 번 밟은 함정). blocks를 추가했으면
   5의 재검산에 더해 **주파 spec 경로**가 걸리지 않는지 확인한다.

## 2. 크기 계산 — 요청서에 크기를 쓰지 않는다 (스킬 1단계)

크기는 생성기가 아니라 `prep-gen <targetH>`가 정한다. targetH는 계산으로:

```
화면 높이(px) = targetH × asset-scale 배율 × 0.5
월드 높이(px) = targetH × 배율
```

- 기준: 서 있는 사람 = 월드 240px. 콘솔·장치 ≈ 220 → **배율 2 기준 targetH 110**
  (1막 장치 6종이 전부 이 값으로 첫 시도에 맞았다 — gen-image-asset 스킬 1단계).
- 자리가 좁은 회랑 장치(ancient-dial·selection-box)는 **허리 높이**로 낮춘다:
  월드 160~180 → targetH 80~90. 폭도 좁게 — 회랑 1.2타일 = 월드 154px(폭)이 상한.
- 빈 자리의 실측이 필요하면 격자 오버레이 합성으로 잰다(재배치 때 만든 방법,
  `docs/dev-history.md` 2026-08-13): 그 자리 아트 px × `background.scale`(방1·2는 2.374,
  방3은 1.771) = 월드 px.

## 3. 요청서 — 방의 지배색을 몸통에, 어포던스는 시안 글로우로

블록 원문은 `docs/gemini-asset-harness.md` §3. 거기에 이 방들의 조건을 더한다:

- **시안 글로우는 전 방 공통이다** — "만질 수 있는 것"의 신호라 방마다 바꾸지 않는다.
- 몸통 재질은 방의 지배색을 따른다(`docs/room-asset-harness.md` §2 배정표):
  방1 = 나무+황동, 온실에 어울리는 빅토리아 실험기구 풍. 방2(만든다면) = 구리+청록.
- 소품 독점표(§2)를 침범하지 않는다 — 난간·유리 표본병 같은 **다른 방의 전유 소품을
  장치 장식으로 그리지 않는다.**
- 받침대 금지 문구(`Do NOT place the object on a coloured plinth, pad or platform`)와
  자홍 배경(#FF00FF)은 스킬 3단계 그대로.
- 레퍼런스 첨부는 스킬 0단계 그대로(`docs/art-style.md`의 `**생성 레퍼런스**:` 줄).
  4개를 **한 요청에 하나씩** 받는다 — 시트로 받으면 isolate-room 신세를 또 진다.

## 4. 절차 (한 개 기준)

```
1) 요청서 작성 (§3) → 생성 → assets-src/gen-src/<이름>.src.png 저장
2) node scripts/probe-bg.mjs <src>                     # 배경색·허용오차 실측
3) node scripts/prep-gen.mjs <src> assets-src/gen/<이름>.png <targetH> <tol> global
4) node scripts/contact-sheet.mjs assets-src/gen/<이름>.png   # 잔재·구멍·헤일로 눈검수
5) Read로 직접 보고 판정 — 형태 뭉개짐·다중 오브젝트면 seed 바꿔 재생성 (품질 게이트)
6) asset-scale.json에 배율 등록 → 맵에 sprite/grounded(/sink/pad) 배선 → npm run assets
7) 게임 스크린샷으로 실제 렌더 확인 (아래 §5)
```

## 5. 합격 판정

- [ ] 타일·range·blocks를 만졌다면: `check-layout 0.4` + `check-reach` + 해당 방 주파 spec

- [ ] **임시 캡처 spec 스크린샷 눈확인** — e2e 통과 ≠ 화면 정상. 볼 것:
  - 장치가 배경에 묻히지 않는가 (1막에서 나방·폐수통 두 번 잡은 단계)
  - 접지가 읽히는가 — 떠 보이면 `sink`↑ 또는 `pad` 추가
  - 캐릭터가 장치 앞에 섰을 때 가림·비율이 자연스러운가 (사람 240 대비)
  - 잠긴 상태 알파 0.4(문)와 구분되는가
- [ ] 캡처 spec 삭제, 회차 기록(§6)에 한 줄
