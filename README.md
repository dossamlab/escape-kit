# escape-kit — 교과 방탈출 저작 키트

성취기준으로 잠긴 방을 만들고, 학생이 **개념을 써서** 그 방을 빠져나가게 하는
웹 방탈출 게임 키트. 브라우저에서 돌고 설치가 필요 없다.

물리 교사가 만든 방탈출 게임에서 엔진과 저작 도구만 떼어 낸 것이다.
예제로 방 하나(「이름 없는 방」 — 탄성파와 소리)가 들어 있고, 그것을 지우고
자기 교과로 다시 채우는 것이 이 키트의 사용법이다.

> **전제**: 이 키트는 [Claude Code](https://claude.com/claude-code)로 쓰도록 만들어졌다.
> `.claude/`에 스킬 6개와 검수 에이전트가 들어 있고, 저작 절차의 대부분이 거기 적혀 있다.
> 코드를 직접 쓸 줄 몰라도 되지만, Claude Code와 대화할 준비는 필요하다.

## 무엇이 들어 있나

| | |
|---|---|
| **엔진** | 아이소메트릭 이동·근접 상호작용·대사·연구노트·수색·인벤토리·키패드 게이트·봉인 구역·저장·엔딩. 교과를 전혀 모른다 |
| **저작 스킬** | `/new-subject` `/add-puzzle` `/add-asset` `/gen-image-asset` `/relayout-room` `/audit-room` |
| **검수 에이전트** | 설계(puzzle-designer)·구현(puzzle-builder)·실플레이(playtester)·아트(asset-artist), 그리고 교과 검수자 |
| **검산 스크립트** | 앵커 참조·근접 판정 간격·에셋 토큰. 전부 `verify.sh`에 물려 있다 |
| **예제** | 방 1개, 퍼즐 5개, 연구노트 6개, 수색 5곳, 완주 e2e |

**의존성은 4개뿐이다** (Vite · TypeScript · Playwright · resvg). 런타임 의존성은 0개.

## 5분 시작

```bash
git clone <이 저장소> my-escape && cd my-escape && npm install && npm run assets && npm run dev
```

`http://localhost:5373`이 열린다. 예제 방을 한 바퀴 돌아 보라 —
암전에서 시작해 진자를 흔들어 불을 켜고, 벽을 두드려 테이프를 찾고, 소리가 죽는 자리를 걸어서
찾고, 현을 짚어 배음을 내고, 마지막에 네 음을 연주해 문을 연다.

**어떤 저작 도구든 결국 이 한 바퀴를 만드는 일이다.** 먼저 플레이해 보는 것이 가장 빠른 설명이다.

## 다른 교과로 바꾸기

Claude Code에서 한 번 실행한다:

```
/new-subject
```

교과·성취기준·모티브 위인·답의 형태를 물은 다음, 이것들을 만든다:

- `.claude/agents/<교과>-reviewer.md` — **네 교과에서 학생이 자주 틀리는 사실 10개를
  프롬프트에 박아 넣은** 검수자. 이후 모든 퍼즐이 이 검수를 통과해야 한다
- `docs/curriculum-map.md` — 성취기준 ↔ 퍼즐 매핑표(+ 출처 + `exceptions` 표)
- `docs/story.md` — 위인 모티브 스토리 뼈대
- `docs/puzzles/room1-overview.md` — 방 슬레이트와 코드 조각 배정표
- `src/config.ts` — 제목·저장 키 등

그다음 퍼즐을 하나씩:

```
/add-puzzle
```

방 배경 그림이 필요하면 `/gen-image-asset`, 좌표를 옮길 일이 생기면 `/relayout-room`,
방이 완성되면 `/audit-room`으로 학습자 눈에서 전수 점검.

### 스토리는 왜 위인에서 시작하나

예제의 화자는 '라플라스'라는 호출명을 쓰는 물리학자다. 그가 **미리 녹음해 둔 안내**만
방에 남아 있고, 플레이어는 그가 어디로 갔는지를 마지막 퍼즐에서 알게 된다.

교사가 직접 설명하지 않고 **그 교과의 인물이 남긴 기록이 말하게 하는 것** —
이게 이식 가능한 부분이다. 세종이 남긴 주석, 퀴리의 실험 일지, 사마천의 사초.
화자를 정하면 방에 놓일 사물과 연구노트가 따라온다.

## 방 하나의 구조

방 하나 = 퍼즐 4개 + 최종 콘솔 1개가 표준이다. 퍼즐 넷이 열쇠를 한 글자씩 내주고,
콘솔이 그 열쇠를 받아 출구를 연다.

- **대사·노트는 전부 `docs/story.md`** — 코드에 문자열을 넣지 않는다.
  `### #앵커` + `> ` 인용 줄이 대사 한 건. 문법 표가 그 파일 맨 위에 있다.
- **방은 `src/maps/<room>.ts` 데이터** — 오브젝트마다 `puzzleId` / `door` / `noteId` /
  `search` / `interactAnchor` 중 무엇을 주느냐가 상호작용 종류를 정한다.
- **퍼즐은 폴더 하나** — `manifest.json` + `puzzle.ts` + `puzzle.css` + `autoplay.ts`.
  정답 상수는 `autoplay.ts`에만 두고 테스트가 거기서 가져다 쓴다.

### 최종 잠금은 세 단계다 — 키패드에 묶이지 않는다

| 단계 | 만드는 법 | 비용 |
|---|---|---|
| ① 숫자 키패드 | manifest에 `gate.code`만 적는다 | 0 |
| ② 라벨 키패드 | `gate.keys`로 키에 아무 글자나 — 자모·한자·연도·시대명·기호 | 몇 줄 |
| ③ **콘솔 퍼즐** | 최종 장치에 `gate` 없이 `puzzleId`만 주고, 그 퍼즐의 `reward.event`를 문이 기다리게 한다. **형태 제한이 없다** | 퍼즐 하나 |

②의 실증이 동봉 예제다 — 코드는 `"1365"`인데 학생이 보는 것은 건반의 **도·미·라·솔**이다.
③의 실증은 한국사 드라이런의 '연대 정리대' — 키패드 대신 **연표에 시대 패를 놓는 퍼즐**이
곧 자물쇠였다(시대 패 여덟 중 넷을 골라 연대순으로 → `door:*-open` 발화 → 문 개방).
교과 특성에 맞는 입력(연표·자모 조합·주기율표·지도)이 필요하면 ③으로 가면 된다 —
퍼즐은 `PuzzleApi`로 DOM을 통째로 받으므로 무엇이든 그릴 수 있다.

## 확인 명령

```bash
bash scripts/verify.sh full
```

story 생성 → **앵커 참조 검산** → 근접 판정 검산 → 타입 검사 → 빌드 → 에셋 →
데스크톱·모바일 e2e. 작업이 끝날 때마다 `quick`, 퍼즐이 완성되면 `full`.

## 알아 둘 한계

정직하게 셋을 적어 둔다.

1. **검산은 수식이 아니라 "결정적 구조"가 있어야 성립한다.**
   물리 예제의 `autoplay.ts`는 수식을 순수 함수로 재구현해 "유일해인가", "개념 없이도
   수렴하는가"를 테스트가 검산했다. 수치가 없어도 **순서·대조·짝맞추기**처럼 판정이
   결정적인 구조를 정답에 쓰면 같은 검산이 성립한다 — 한국사 드라이런(유물 층위 퍼즐)에서
   전 순열 유일해·수렴 상한을 순수 함수로 증명했다. 반대로 자유 서술처럼 결정적 판정이
   없는 답을 쓰면 `autoplay.ts`는 상수 파일로 줄고, 대체 수단은 `playtester`의 실플레이뿐이다 —
   **힌트를 열지 않고 한 번 풀어 보는 절차를 건너뛰지 말 것.**

2. **방 배경 그림의 좌표 보정은 편집이 아니라 노동이다.**
   생성 이미지 한 장마다 `scripts/measure-room.mjs`로 바닥 마름모를 재서
   `scale`·`offsetX`·`offsetY`를 손으로 넣어야 한다. `/gen-image-asset`과
   `/relayout-room`이 절차를 문서화해 두었지만 왕복이 생기는 단계다.

3. **문서화된 함정 셋** — 전부 실제로 당한 것들이다.
   `GameMap.epilogue`를 안 주면 엔진 기본 대사로 방이 끝난다 /
   `sealed.opensWhen`에 봉인 **안쪽** 퍼즐을 걸면 그 구역은 영영 안 열린다(런타임 검사 없음) /
   `sealed.area`가 벽 띠를 안 덮으면 봉인 너머로 반짝임이 샌다.
