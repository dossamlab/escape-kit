name: audit-room
description: 완성된 방을 학습자 눈으로 전수 점검. 텍스트 정적 스캔→오답 포함 실플레이→
  UI 충돌 확인→수정. (퍼즐 하나 검수는 add-puzzle의 playtester)
---
1. **스캔 대상을 빠짐없이 센다**: 매니페스트 전부의 `principle`·`hints`, 연구노트 전부,
   수색 텍스트 전부, `docs/story.md` 앵커 전부, 퍼즐 런타임 문자열(명판·상태문·
   성공/실패 피드백 — 소스에서 `textContent|innerHTML`로 훑는다). 하나라도 빼면
   거기서 나온다 — 원리 카드가 멀쩡한데 성공 피드백만 틀린 적이 있다.
2. **표기**: 학년 수준에 낯선 표기 금지(`a^{3/2}` → `T² = a³`).
   기호·−(U+2212) 통일 — `toFixed`는 ASCII 하이픈을 내놓으므로 치환 헬퍼로 감싼다.
   같은 개념은 한 이름으로(화면에 없는 번호를 대사가 부르고 있었다).
3. **교과 정확성** — `<교과>-reviewer` 에이전트에 위임하고, 최소한 이 셋은 직접 본다:
   - **계산 검산**: 결과를 문자열에 하드코딩하지 말고 **상수로 계산해 단위와 함께** 찍는다.
     (실사례: `1200 × 5.0 = 6.0 kN`이 단위 깨진 채 성공 화면에 떠 있었다 — 곱은 6,000 N)
   - **사실 검산**: 실제 값으로 못 박은 설정은 원 자료로 되짚는다. 그럴듯한 숫자가
     가장 위험하다. (실사례: 고도차 시간 지연이 1,000배 과대였다)
   - **오개념**: 노트·힌트가 **오답 유인값을 가리키지 않는지**. 정확히 그 퍼즐의
     대표 오답으로 유도하는 문장이 힌트에 있던 적이 있다.
4. **정합성**: 서열·배열을 언급하는 대사는 실제 정답 배열과 대조("세 번째로 깊은" ← 실제 2번).
   앞 방을 잇는 대사는 **앞 방 `story.md` 앵커를 직접 연다** — 요약은 인물 관계의 방향을
   잃는다(등호를 반대로 읽어 프롤로그를 다시 쓴 적이 있다).
5. **생성 파이프라인 검산**: `npm run story` 산출물에서 `"` 개수가 홀수인 문자열을 찾는다
   (build-story가 문단 앞뒤 따옴표를 각각 벗겨 닫는 쪽만 사라진 사고 — 3곳).
   앵커 참조 오타는 `node scripts/check-anchors.mjs`가 잡는다(verify에 편입돼 있다).
6. **실플레이**: 임시 스펙 `tests/e2e/_manual-check.spec.ts`로 노트 전수 수집 + 각 퍼즐을
   **오답 한 번 → 정답** 순으로 실제로 풀고 캡처한다. 오답 피드백은 오개념을 바로잡는
   자리라 반드시 띄워 본다. 확인 후 스펙 삭제.
   함정: 실행 중 소스를 고치면 **HMR 전체 리로드로 플레이가 끊긴다**(수정은 몰아서).
   노트는 `note-overlay`(수색은 `discovery-overlay`). E는 **닫기 키이기도 해서**
   재시도 루프로 여러 번 누르면 열자마자 닫힌다 — 라벨을 기다렸다 한 번만 누른다.
7. **UI 충돌은 모바일 폭에서 본다.** 데스크톱은 오버레이가 가운데 정렬이라 z-order
   충돌이 안 보인다(뮤트 버튼 z-index 90 > 모달 50~80을 여태 못 봤다). 체크: ✕가 본문을
   가리는가(제목 `min-height`로 구조적 차단) / 드래그 히트 영역을 뒤에 append된 요소가
   가로채는가(`> * { pointer-events:none }` + 히트만 `auto`) / 도면이 남는 폭을 쓰는가
   (`flex: 1 1 Npx; width: min(Mpx, 100%)`) / 가로 스크롤이 생기는가.
8. **마무리**: `bash scripts/verify.sh full`(flaky 0) → `docs/dev-history.md`에 찾은 것과
   **"문제 없던 것"까지** 기록(다음 점검의 범위가 된다). 커밋은 사용자가 "커밋"이라 할 때만.
