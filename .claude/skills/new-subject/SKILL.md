동봉된 물리 예제를 네 교과의 방탈출로 바꾸는 **최초 1회** 절차다.
코드는 거의 안 건드린다 — 이 저장소는 이미 교과 중립이고, 바꿀 것은 **데이터와 검수자**다.

## 0. 먼저 알린다

작업 전에 사용자에게 이 한 줄을 확인받는다:
> "예제(물리 청음실)의 방·퍼즐·스토리를 지우고 새 교과로 시작합니다. 되돌리려면 git이 필요합니다."

## 1. 인터뷰 (한 번에 다 묻지 말고 2~3덩이로 나눠 묻는다)

1. **교과·과목·학년** — 예: "국어 / 언어와 매체 / 고2"
2. **성취기준** — 다룰 성취기준의 **원문**을 붙여넣거나 출처 URL을 받는다.
   ⚠ 기억으로 코드를 지어내지 않는다. 받지 못했으면 WebSearch로 찾아 **사용자에게 확인받고**,
   확인 전에는 매핑표에 `(코드 검증 예정)`으로 적는다.
3. **모티브** — 이 교과의 위인·일화·사건 1~3개. "누가 남긴 기록이 말을 거는가."
   후보가 없으면 교과 특성에 맞는 후보 3명을 근거와 함께 **제안하고 고르게 한다.**
4. **규모** — 방 개수(**1개 권장**). 방 하나 = 퍼즐 4개 + 최종 콘솔 1개가 표준 슬레이트다.
5. **답의 형태** — 최종 열쇠가 무엇으로 이루어지는가: 숫자 / 자모 / 한자 / 연도 / 기호 /
   사건 이름. (`gate.keys`의 `label`이 그대로 화면에 뜬다. `freq`는 안 줘도 된다.)

## 2. 오답 상수 채굴 ← **이 스킬의 품질은 여기서 갈린다**

사용자에게 묻는다:
> "이 단원에서 학생들이 **가장 많이 틀리는** 사실·표기·연표·수치·개념 혼동을 10개만 적어 주세요."

답이 부실하면 WebSearch로 보강하고 **반드시 사용자 확인을 받는다.**
이 10개가 다음 단계에서 검수자 프롬프트에 **상수로 박힌다** — 검수 품질의 전부다.
(동봉된 `physics-reviewer.md`가 그 형식이다: 발머 계열 파장 656/486/434/410 nm처럼
"틀리면 바로 알 수 있는 값"을 프롬프트가 직접 들고 있다.)

## 3. 산출물

| # | 파일 | 내용 |
|---|---|---|
| 3-1 | `.claude/agents/<교과>-reviewer.md` | `physics-reviewer.md` 골격 + **2단계의 상수 10개를 본문에 박아 넣는다**. 그다음 `physics-reviewer.md`를 지운다 |
| 3-2 | `docs/curriculum-map.md` | 범위 규칙 절 + 방↔단원 표 + 퍼즐↔성취기준 표(**검증 출처 열 포함**) + `exceptions` 표. 형식은 기존 파일 그대로 |
| 3-3 | `docs/story.md` | 헤더의 **문법 계약 표는 그대로 두고** 설정·프롤로그·방 섹션만 새로 쓴다. 노트 구분자는 EM DASH(—, U+2014) |
| 3-4 | `docs/puzzles/room1-overview.md` | 방 슬레이트: 퍼즐 4 + 콘솔 1, 각 퍼즐이 내주는 **코드 조각 배정표**, 봉인 구조(쓸 거면). 형식은 동봉된 `room3-overview.md` |
| 3-5 | `src/config.ts` | 8개 상수 치환. `index.html`의 `<title>`·og 메타도 함께 (config가 못 닿는 자리) |

`exceptions` 표를 빼먹지 말 것 — "성취기준과 100% 안 맞아도 되지만 불일치는 명시하고
승인받는다"는 감사 장치이고, 이게 없으면 매핑이 슬그머니 어긋난다.

## 4. 예제 걷어내기

산출물이 준비되면 지운다:
- `src/puzzles/*` 전부, `src/maps/sonic-room.ts`, `src/registry.ts`·`src/maps/index.ts`의 등록
- `tests/e2e/`의 퍼즐 spec들 (`helpers.ts`·`smoke`·`save`·`search`·`puzzle-layout`은 **남긴다** —
  좌표와 문구만 새 방에 맞게 고친다)
- `docs/puzzles/room3-overview.md`, `docs/room3-asset-spec.md`, `assets-src/gen*`의 예제 스프라이트
- `docs/dev-history.md`는 비우고 새로 시작한다

## 5. 마무리

`npm run story && npm run typecheck`가 통과하는지 본다. 이 시점에는 방이 없어 게임이
돌지 않는 게 정상이다 — 다음은 `add-puzzle` 스킬로 첫 퍼즐을 만드는 것이다.
사용자에게 다음 한 줄을 안내한다:
> "이제 `/add-puzzle`로 첫 퍼즐을 만듭니다. 방 배경 아트가 필요하면 `/gen-image-asset`."

## 하지 않는 것

- **엔진(`src/engine/`)은 건드리지 않는다.** 건드려야 한다면 그건 이 키트의 버그다 — 보고할 것.
- 성취기준 코드를 추측으로 적지 않는다.
- 사용자 승인 없이 예제를 지우지 않는다(0단계).
