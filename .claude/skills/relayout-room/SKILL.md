1. **무엇이 N에 비례하는지 먼저 안다.** 배경 그림 속 가구는 월드 폭 `N×128`에 맞춰
   늘어나 **N에 비례**하고, 캐릭터·장치 스프라이트는 월드 고정 크기라 **무관**하다
   (캐릭터 = 50px × scale 5 = 월드 250px = 화면 125px). 그래서 N을 줄이면 가구만
   작아진다 — 방 크기를 바꾸는 진짜 이유는 인물:가구 비율이지 "넓이"가 아니다.
   N을 새로 정하는 계산은 **gen-image-asset** 8항에 있다(락커 아트 픽셀 하나로 역산).
2. **함께 옮길 것**: 스테이션·연구노트·수색 핫스팟 좌표, `blocks` 띠, `spawn`,
   그리고 **수색 `range`** — 벽면 가구는 격자 **바깥**에 그려져 있어 사거리로 도달하는
   구조라 `×새N/옛N`으로 같이 키워야 한다(안 키우면 벽에서 안 닿는다. 14→20에서
   2.4 → 3.4). e2e 헬퍼·spec의 좌표도 같은 값으로 고친다.
3. **근접 판정은 범위 안 최근접 하나만 고른다.** 그래서 가까이 붙은 두 대상은 서로
   라벨을 가로챈다 — 문↔콘솔이 2.24타일이었을 때 문 앞 라벨이 "시계 격리 콘솔"로 떠
   smoke가 깨졌다(지금 3.6타일). 사거리를 넓힌 수색 핫스팟끼리도 첫 배치에서 3곳이 그랬다.
4. **검산**: `cd act2 && node scripts/check-layout.mjs 0.4` — ①전 쌍 1.5타일 이상
   ②각 대상의 접근 지점에서 근접 판정이 그 대상을 고르는지(정지 오차만큼 사방으로 흔들어
   최악까지). `verify.sh`에 이미 편입돼 있으니 좌표를 만졌으면 여기서 먼저 걸린다.
5. **검산값과 e2e 접근 오차를 반드시 같게 둔다.** 0.4로 검산해 놓고 헬퍼는 1.0으로
   접근하고 있어 flaky가 났다(콘솔 앞에 서려다 옆 연구노트가 더 가까워짐). 지금은
   `tests/e2e/helpers.ts`의 `APPROACH_THRESHOLD` 하나로 통일하고 양쪽 주석에 "이 둘은
   반드시 같아야 한다"를 못박아 뒀다 — **임계값을 바꾸면 두 곳 다 바꾼다.**
6. **여유 확인**: `check-layout`을 0.5·0.7·1.0으로도 돌려 어디서 깨지는지 본다.
   0.4에서만 안전하면 그게 임계값이다.
7. **검증**: `bash scripts/verify.sh full`. 좌표에 가장 민감한 순서로 본다 —
   smoke(문 앞 라벨) → search(핫스팟 가로채기) → playthrough(전체 주파). **flaky 0** 확인.
8. **문서**: 맵 파일 상단 주석에 "왜 이 N인가"를 실측값과 함께 남기고(다음 사람이 다시
   눈대중하지 않도록) `docs/dev-history.md`에 경위를 기록한다.

## 도구 — 눈대중하지 않는 방법 (2026-08-19 신설)

**화면에서 픽셀을 눈으로 읽으면 틀린다.** 실측으로 일관되게 ~45px(≈0.85타일) 어긋났다.
믿을 수 있는 것은 둘뿐이다 — ① **같은 그림 위에 찍은 점끼리의 상대 비교** ② **사용자가 직접 찍기**.

### 1. `tools/tiles.html` — 걷기 영역·핫스팟을 그림 위에서 직접 찍는다

개발 서버로 연다: `http://localhost:5373/tools/tiles.html`
(주소는 `npm run dev` 시작 로그에도 찍히고, `npm run tiles`가 열기 전 조건까지 검사해 준다.)
(Vite 개발 서버는 루트 파일을 그대로 서빙한다. `public/`이 아니라 `tools/`에 두는 이유는
**빌드 산출물에 안 들어가게** 하려는 것이다 — `dist`에는 `public/`만 복사된다.)

- 드래그로 **막힘 칠하기**(빨강 = 못 걷는 칸), 모드 전환 후 **핫스팟 클릭**.
- **열면 지금 맵의 `blocks`가 이미 칠해져 있다.** 방 목록·캘리브레이션·핫스팟까지
  `src/maps/index.ts`를 import해서 읽으므로 손으로 맞출 사본이 없다(2026-08-20).
  「맵 상태로 되돌리기」로 언제든 원래 상태로 돌아온다. 「전부 지우기」는 빈 판이다.
- 출력은 ASCII 막힘 지도 + 핫스팟 목록. 그대로 복사해 아래 스크립트에 먹인다.

### 2. `scripts/blocks-from-mark.mjs` — ASCII 마킹 → `blocks` 사각형

```bash
node scripts/blocks-from-mark.mjs mark.txt
```

칠한 타일을 **최소 개수의 사각형**으로 묶는다(방당 9~11개). 가장자리 사각형은 격자 밖까지
늘려 준다. 타일 `t`는 연속좌표 `[t-0.5, t+0.5]`를 덮는다 — `isBlocked`가 경계 포함이라 그렇다.

### 3. `scripts/annotate-room.mjs` — 그림 위에 격자·blocks·핫스팟을 얹어 눈으로 본다

```bash
node scripts/annotate-room.mjs room2-energy out.png hot
```

`grid`(좌표 라벨) · `hot`(+blocks+핫스팟) · `pts`(후보점 비교) · `guide`(벽면 세로 가이드).
캘리브레이션을 바꿔 보려면 맵을 건드리지 말고 환경변수로:

```bash
OVER_N=15 OVER_OX=-1269 OVER_OY=-538 node scripts/annotate-room.mjs room2-energy out.png grid
```

⚠ `guide` 모드는 **격자 평면 위의 사물에만 맞는다.** 벽에 그려진 문·지도는 바닥 평면 밖이라
세로 가이드로 x를 읽으면 틀린다(2026-08-19에 이걸로 한 번 헤맸다).

## 원점을 옮기는 계산 (격자가 그림 바닥보다 작을 때)

격자가 그림보다 작아 **벽면 사물 앞까지 걸어갈 수 없으면** 원점을 옮긴다.
`scale`·`scaleY`는 건드리지 않는다(그림 크기와 인물:가구 비율이 바뀐다).

타일 `(a, b)`만큼 격자를 넓히려면 — 즉 옛 `(x, y)`가 새 `(x+a, y+b)`가 되게 하려면:

```
offsetX_new = offsetX_old − (a − b) × TILE_W / 2      // TILE_W = 128
offsetY_new = offsetY_old + (a + b) × TILE_H / 2      // TILE_H = 64
```

2열·3행이면 `offsetX −64`, `offsetY +160`이다. `cols`·`rows`도 그만큼 키운다.
**남는 쪽(그림 밖으로 나가는 행·열)은 버리는 것이 정상이다** — 어차피 못 걷는 칸이었다.

## 좌표를 정할 때 지켜야 할 부등식 셋 (전부 실패로 배웠다)

1. **핫스팟은 가장자리에서 `margin 0.4`보다 안쪽에.** 캐릭터가 `margin`까지밖에 못 가므로
   `x=0`에 둔 장치는 거리 0.4가 임계 0.4를 못 넘어 영원히 안 잡힌다 → `x=0.5`.
2. **블록 경계선 위에 목표를 두지 않는다.** 그리디 이동이 경계에 붙어 멈춘다.
   `y=9.5`(수로 경계와 같은 값)는 실패, `y=9.8`은 통과.
3. **경유점 + 임계 < range**, 그리고 **경유점은 착지 오차만큼 여유를 둔다.**
   임계 0.4로 밟는 경유점은 최악 0.4만큼 어긋난 자리에서 다음 다리가 시작된다 —
   그 자리에서도 다음 목표에 닿는지 확인할 것. `range`를 조이면 **spec의 접근 오프셋도
   같이 본다**(`dy + 1.1` + 임계 0.6이면 최악 1.7이라 range 1.4 밖이다).
